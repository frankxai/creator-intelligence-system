# Creator Intelligence System — repository agent instructions

## Scope and priorities

These instructions apply only when an agent works **inside this repository**. For media/product-demo/carousel/animation/DAM/publishing tasks, use `docs/MEDIA_EXCELLENCE_PLAYBOOK.md` and the existing `docs/VIDEO_PRODUCTION_OS.md`. Preserve CIP contracts and existing implementation decisions; an outdated README or historical plan is not higher authority than current verified code and exact release receipts.

For unrelated tasks, obey the applicable repository instructions and do not inject media workflows indiscriminately.

## Default media workflow

1. Discover the requested brand, audience, conversion job, existing work/asset IDs and highest-authority verified sources. Do not repeatedly ask for known context.
2. Differentiate `PROPOSED`, `SOURCE_READY`, `RENDERED`, `QA_PASS`, `FOUNDER_APPROVED`, `PUBLISHED`, `PERFORMANCE_OBSERVED`; cite exact artifact hashes/revisions and URLs for positive claims. `UNKNOWN` remains unknown.
3. Choose one original narrative with genuine evidence. Still-first composition, verified identity, legibility and brand differentiation are release gates; decorative motion and generic nested-card dashboards fail.
4. Convert from one editable scene / CIP-linked media manifest into purpose-designed format variants. Prefer real captured UI for product proof; HyperFrames for new deterministic motion; Remotion for existing React-specific compositions; Descript for performance edits; Higgsfield for non-proof cinematic B-roll, subject to current runtime verification.
5. Do not conflate ChatGPT widgets with exportable source code or a concept shot with a verified live product. Rebuild approved scenes in version-controlled HTML/SVG/React when needed, and inspect actual renders.
6. Use available tools to implement, test and inspect now. Missing shell, renderer, model, credentials, account permissions or approvals blocks only the affected step; do not invent execution or backend agents.
7. Preserve source and rights, input fixture and output hashes, approval revision, destination account and publisher receipts. No automatic publishing, paid retries or PR merge without authorization and appropriate gates.
8. End with shipped evidence, unresolved gates and one next actionable owner. A proposal is never represented as deployed infrastructure.

## Cross-host activation boundary

Repo `AGENTS.md` can guide GitHub/Codex agents in this checkout; it cannot install a ChatGPT plugin, automatically activate unrelated conversations, schedule unattended work or grant external tool access. The optional private `starlight-media-excellence` plugin contains matching ChatGPT skills, with host-dependent invocation.
